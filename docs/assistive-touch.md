# AssistiveTouch 返回主屏幕

**仅在明确要求返回主屏幕或恢复操作时使用**，普通输入/回复流程不要先回主屏幕。
`Phone.go_home()` 优先点击辅助触控悬浮按钮，等待菜单稳定，再点击「主屏幕」。
使用统一的受保护点击路径：把当前可见按钮圆环/菜单图标的实际边界传给 `tap`。
指针不可见时，只有校准及已测落点误差覆盖这个目标且小于安全余量才允许点击；否则拒绝。
历史坐标和面板内的推算位置本身不能提供目标大小。
需要已校准的鼠标和实时镜像；按钮识别支持屏幕边缘的圆环、圆角方框及淡出的 iOS 26 外观。

菜单识别要求圆角深色面板，以及顶部中央、左右两列、底部中央六个区域的图标证据；
普通深色对话框不算菜单。菜单位置按面板边界计算。默认六图标菜单的 Home 图标取面板内
`(0.5, 0.82)`，即底部中央。此默认值依据现有操作记录；可用素材中没有打开的菜单截图，
仍需在真机确认。保持六图标排列的自定义菜单可调整 Home 位置或接入文字识别；
其他图标数量或排列会被保守拒绝，进入 HID 退路。

成功检查要求实时、符合共享新鲜度规则的画面中菜单消失，并有**主屏幕的正面证据**：
至少两排对齐的 App 图标、底部独立 Dock 容器中的至少三个 App 图标，且没有顶部 App 工具栏横线。
图标大小须接近；结果还须连续 0.2 秒稳定。菜单点击前会同时比较面板边界和内容，等待超时不算稳定。
仅关闭菜单、App 内容变化或板子 ACK 都不算成功。未看到上述特征会明确报「未确认主屏幕」。
这是保守的竖屏图标页识别；只有小组件的页面、图标较少、横屏、App 资源库或特殊主题可能拒绝，
需要主人观察确认。它不是操作系统的内部状态证明，也不能识别刻意仿造主屏幕的画面。

如果当前画面足够新鲜，但按钮/菜单未找到或未看到主屏幕结果，会依次尝试并记录日志：

1. 从底部上滑。
2. 固件 `homescreen`（Consumer AC Home，0x0223）；不支持时继续下一步。
3. `key cmd+h`。

确认主屏幕特征即停止后续尝试；均不能确认则报告失败。开始操作和每条退路之前均须通过共享新鲜度检查；
无镜像、旧视频重放、断线重连或点击前目标检查失败会立即停止，不继续发送恢复命令。
紧急停止和任务取消也不会触发后续退路。`go_back()` 不变。

## 位置和菜单配置

首次成功打开菜单后，悬浮按钮坐标和画面宽高比自动写入校准文件旁的
`calibration.assistive-touch.json`。宽高比相近时记录的位置仅用于给可见候选排序；
按钮移动后使用当前检测位置，识别不到就进入 HID 退路，不点击历史位置。校准文件本身不改动。

服务启动前可以配置固定的屏幕归一化坐标：

```sh
export HIDAGENT_ASSISTIVE_TOUCH_POSITION=0.91,0.782
```

也可以编辑 `calibration.assistive-touch.json`，保留需要的字段并重启服务：

```json
{
  "position": [0.91, 0.782],
  "layout": {"home": [0.5, 0.82]}
}
```

`position` 相对整张画面；`layout.home` 相对检测出的面板，两者均为 `[x, y]`，范围 0–1。
固定位置优先级为构造参数、环境变量、JSON 文件。点击前仍须在该位置附近检测到可见按钮
（归一化距离不超过 0.025），否则进入 HID 退路。固定位置应在旋转屏幕或移动按钮后更新。
去掉 `position` 并清除环境变量即可恢复自动检测。

## OCR 接口

无需增加依赖即可传入同步函数 `find_text(frame: bytes, text: str) -> (x, y) | None`：

```python
phone = Phone(device, calibration_path, screen, find_text=find_text)
# 也可以在现有对象上接入：
phone.assistive_touch.find_text = find_text
```

`frame` 是镜像图片字节，返回值是整张画面的归一化坐标。依次查询「主屏幕」和 `Home`，
只在已通过图标检查的菜单内接受结果；点击点还须落在一个当前可见图标的边界内。
旧接口只返回文字中心，无法提供文字框大小，因此指向标签而非图标的结果可能被拒绝。没有匹配、坐标无效或 OCR 出错时使用布局，
错误日志不包含 OCR 异常内容。其他语言需在回调中做
标签映射，或配置 Home 图标位置。构造参数 `assistive_touch_position=(x, y)` 和
`assistive_touch_layout={"home": (x, y)}` 也可用于嵌入式调用。

## 真机待验

检查不同背景、透明度和屏幕方向下的按钮识别；菜单边界和默认 Home 中心位置；
自定义菜单及系统语言；已有校准下两次实际点击的落点；镜像延迟时的结果验证。
打开菜单和结果各等待最多约 3 秒，包含 0.2 秒稳定区间；所有按钮、菜单及结果画面使用共享新鲜度判断；结果还须满足动作后的时间/镜像延迟限制。
低对比度、遮挡、与菜单相似的 App 面板仍可能使视觉判断失败。
此路径从关闭的辅助触控菜单开始；不会仅凭一张深色面板截图猜测已经打开的菜单内容。

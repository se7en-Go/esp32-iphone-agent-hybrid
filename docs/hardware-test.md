# 待 seven 实测（按可行性报告第 9 节的顺序）

本仓库没有 iPhone，也没有 N16R8。下面每一项都还没在真机上做过。不要根据 CI 绿灯推断手机已经能动。

1. **烧录和串口。** N16R8 能写入预编译固件。电脑把 COM 口认成 CH343。`0 status` 有 JSON 回复。Windows 上如果没有 COM 口，先装沁恒 CH343 驱动。
2. **HID 和供电。** 标着 USB 的口经数据线（Lightning 手机用相机转换器）接 iPhone。手机把它认成鼠标键盘，辅助触控的圆点会动。同时看供电：会不会弹出「配件耗电量太大」，串口 `rst` 会不会变成 brownout。板子上 USB-OTG / IN-OUT 焊盘必须是断开的，否则电脑的 5V 会倒灌给手机。
3. **STA 和屏幕镜像（最关键的未知项）。** 配网脚本写入家里的 2.4GHz 后，iOS 17 的控制中心「屏幕镜像」列表里能看到 **ESP32 Agent**，并且开始出画面。这一步上游没在 iOS 16/17 的板载接收器上测过。失败时的退路：把手机升到 iOS 18；或只在 Mac 上设 `SCREEN_BACKEND=uxplay`（要自己装 UxPlay 和 GStreamer，Windows 不要走这条）。
4. **7201。** 电脑从 `0 netinfo` 拿到 vtok（不要把其中的 Wi-Fi 密码贴出去）。网页 `http://127.0.0.1:8890` 能看到画面。PyAV 解出来的是手机屏幕，不是花屏。
5. **指针和中文。** 校准后，Agent 把指针移到屏幕中央并停住，位置和截图一致，这一步不要点击。然后输入「谢谢分享」：核对候选，核对输入框里的最终汉字。按 skill 发送时，只有看到完整的新气泡才算成功。
6. **另一台电脑。** Windows 10/11 原生走同一套脚本（不打开 Linux 子系统）。同一块板子、同一台手机，换一台电脑不用重烧固件，只把 COM 线换过去。若换了网络，再跑一次配网脚本。

锁屏后再解锁，镜像会停，需要重新选一次「ESP32 Agent」。这是预期行为，不是脚本坏了。

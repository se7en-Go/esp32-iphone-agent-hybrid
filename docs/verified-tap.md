# iOS 26 点击：落点保护与反馈

`POST /api/control/action` 的 `tap` 使用观察返回的单次 `screen_id`。
时钟和可辨认的指针/按钮悬停高亮可以变化；页面、滚动、弹窗、目标附近的内容变化必须重新观察。
屏幕 ID 的宽容匹配不是新鲜度证明，也不能证明聊天对象、输入框焦点或发送目标正确。
这些关键上下文应单独核对。没有跳过校验的 `latest` ID。

## 什么时候允许点击

所有点击先使用共享的新鲜度检查；取得设备命令锁后，在实际串口写入之前
再次检查新鲜度、连接代数、目标和上下文。检查到写入期间持有画面发布锁，
因此等待设备忙碌时发生的页面变化不能通过旧检查发送点击。
断流、过老的帧、板子重放、没有可用板子时钟的带时间戳视频均不能当作当前画面。
板子时间戳表示视频到达板子的时间，不是 iPhone 拍摄时间。

定位使用校准和已学习的落点。可信指针已位于容差范围内时可以点击；
指针隐藏、变成高亮或一次修正之后仍未重新看见时，只有同时满足以下条件才允许使用预计落点：

1. 提供本次观察中的目标矩形 `target_box`（归一化的左、上、右、下）以及观察帧。
   OCR 的 `tap_text` 自动提供文字框；普通坐标点击不能仅凭坐标推断按钮大小。
2. 目标和上下文在定位期间未变化。检查保留目标内容，只排除可信指针覆盖。
3. 每个轴至少有三个已测落点，测量覆盖目标，不能外推。两个自动校准点本身只是拟合，
   不足以验证误差；手动单点校准也不够。
4. 已测逆向校正拟合残差的最大值加上 `0.008` 屏幕比例安全余量，不超过目标最近边缘距离的一半。
   小按钮或误差较大的校准会被拒绝。历史测量不能保证未来绝对准确，仍须真机核验。

不满足条件会明确报错且不发 `click`。不会因为找不到指针而继续反复修正或盲点。
一次可信但偏移的读数最多触发一次修正；修正后的未观察落点仍需上述保护。

## 指针观察

移动本身会唤醒指针，因此日常定位后先检查实际移动产生的新帧，不再每次额外轻推。
只有确实需要搜索、指针原地且已闲置至少三秒时，才使用唤醒轻推；
已有安全预计落点的目标连这次唤醒也会跳过。
不能安全预计落点时，会给真实移动的指针帧最多 2 秒；若初始指针未知或已淡出，
再使用一次 12 单位定位往返，每个方向最多 2 秒，必须看见与本次命令相关的成对圆点才确认。
这属于必要的定位，不是每次观察都执行的唤醒。定位未确认就不点击。
检查只接受定位完成之后的帧，旧帧不能触发修正或污染学习记录。
修正后的成对圆点必须显示原圆点已经离开、相同大小和颜色的圆点沿预期方向到达。
小于一个指针直径的移动也可确认；仍在原位置的静态圆形不会被当作运动证据。
缺少捕获时序或镜像延迟超过短搜索窗口时，不能把一个旧圆点当作当前落点。
自动/手动校准仍保留较长探测路径。自动校准也保留每次轻推的动作时刻，按同一
动作后新鲜度规则筛选，不会把刚收到、实际早于轻推的排队图像学进校准。
若唯一的轻推图像在 1.7 秒不确定窗口内到达，此后静止无帧，自动校准可能失败，
需要按提示手动校准；不能以旧运动换取一次虚假的自动成功。

原点左侧/上方的目标保留负偏移，不会静默压成原点。从 `home` 出发时先离开圆角进入内部，
再分轴移动到负偏移目标；从已知位置可直接相对移动。真实圆角边界仍需手机确认，
特别是微信 `(0.08, …)` 返回位置。未经落点测量的这些边缘目标不能自动获得盲点资格。

## 返回结果与耗时

`clicked` 仅表示设备应答；`pointer_seen` 表示看见过可信指针。
`effect_observed` / `screen_changed` 只表示视觉证据，动画也可能产生变化；
`effect_verified` 始终为 `false`，因为画面变化不能验证预期效果。
没有合格的后续帧时 `effect_observed` 为 `null`，不能报告成功。
返回警告要求调用者核对截图，不自动重试点击。
Agent 也会立即阻止重复提出上一轮结果未知的同一点击（坐标点击或 OCR 点击）；
再次观察到相同截图、只读 OCR 查询或重新规划不能证明前一次失败，不会解除这个保护。
点击命令写出后若应答丢失，Agent 会在重连和重新规划之前保留该次尝试，标为
`outcome: unknown`；不能因为没有收到 ACK 就自动补点一次。

`batch` 中的点击结果未验证时，后续步骤立即停止；没有新帧、连接代次变化或上下文变化
也会停止。返回 `completed`（已应答的步骤数）和 `stopped_before_step`（未执行的下一步，
从 1 开始）。步骤中的 `ok` 只表示命令已应答，不表示点击效果正确。
输入文字和键盘动作（包括 Enter、换行、编辑键）必须是新观察后的第一步；
例如点击输入框后，先检查新截图中的焦点，再单独输入，不能在同一批次中直接继续。
单次编辑动作的 `repeat` 仍支持退格/左右键；发送不会自动重试。
没有合格后续帧的返回结果不提供可操作的 `screen_id`（为 `null`）；
其中的截图只帮助解释不确定状态。先重新观察并核对焦点，再提交输入动作。

`timing_ms` 分别记录：

- `positioning`：定位观察、目标检查等主机工作，不包含下项的命令等待。
- `firmware`：实际命令从发送到 ACK 的等待，包含固件执行和传输延迟，不是纯 CPU 时间。
- `wait_for_frames`：等待点击之后的合格帧。
- `diff`：像素变化比较时间。
- `total`：完整调用时间。控制接口另有验证/截图等开销。

假设备按固件每 10 单位一份、每份 8 ms 的节拍移动，点击保持 60 ms。
从原点到 `(0.5, 0.44)` 的命令时间为 **620 ms**，从 `(0.5, 0.55)` 为 **196 ms**，
都不含已删除的固定轻推。叠加 1.7 秒镜像延迟，最低就约 **2.32 s / 1.90 s**，
还要加目标校验、真实串口应答、时钟查询和图像比较。没有统一的 1–2 秒承诺。
回归测试按板子实际收帧时刻打时间戳，不能减去镜像延迟冒充拍摄时刻。
只有早到的一帧时，预算包括完整的 3.45 秒证据等待窗口；有合格后续帧时，
按命令耗时 + 实际帧等待 + 400 ms 主机开销设预算，并输出每个阶段的实际数值。
上述数字是已具备安全预计落点的路径；必须视觉定位的小控件还要计入至多 2 秒观察及
两个至多 2 秒定位方向窗口，不能把它们宣传成同样耗时。

无论有无板子时钟，都必须留出 1.7 秒的手机到板子镜像不确定区间，
再留 1.75 秒反馈窗口。有时钟时还要加上时钟查询不确定度；板端接收时间
早于该边界的帧不能作为点击后的证据。只有能证明在点击前已到达板子的帧
才更新比较基线；不确定区间内的图像也可能已包含点击结果，不能抹去原来的比较基线。
屏幕静止而不再发送帧时会诚实报告未知。
同一次点击的后续截图和差异复用已接受的那一帧，不再重复等待或进行第二次完整 OCR。
真实硬件仍需验证落点误差、圆角、指针形态、镜像延迟及全过程耗时。

普通坐标接口和内置 Agent 也走同一保护；只有显式 `home`/恢复会调用 AssistiveTouch。
`target_box` 必须来自刚观察的实际控件，而不是为了绕过保护随意扩大。
共享帧条件：主机接收不超过 5 秒；带板端时间戳时必须有当前连接的时钟，
板端积压加时钟查询不确定度不得超过 2 秒。安静的传输连接不能证明旧画面仍可用于操作。
对于仍连接、上次帧接收时没有重放但静止超过 5 秒的画面，观察或操作会进行
一次最长 3.5 秒的重新获取：轻推 2 单位，等待镜像不确定区间，再回移 2 单位
促使 AirPlay 发布新帧。只接受通过同一新鲜度检查的新帧；重放、断开或超时仍拒绝点击。
该过程与其它 Phone 手势串行，不会在拖动、输入或点击中途插入轻推；当前位置记录
会失效，以免边缘裁剪后的偏移继续被当作准确位置。新鲜画面不会触发此过程。
已保存的落点未按方向、路径和时间分别建模；改变指针速度/缩放或设备后应重新校准并测量。

# iOS 26 点击反馈

`POST /api/control/action` 的 `tap` 仍使用观察返回的单次 `screen_id`。
时钟、指针出现/消失、小幅移动及可辨认的按钮高亮轮廓不再轻易使它失效；页面切换、滚动、弹窗等明显变化仍会拒绝操作。
有效期仍为 30 秒，已消费的 ID 不能重用，也没有绕过校验的 `latest` ID。

点击先使用校准和已学习的落点移动，再轻推 2 个单位并退回以唤醒指针。
最多用 120 ms 尝试寻找成对移动的圆形指针；可信落点距目标不超过 `MAX_MISS` 时最多修正一次。
只接受本次定位完成后拍摄、时间戳能对应到本次轻推或退回的帧对，不从排队旧帧修正或学习。
缺少板子时间戳或已知镜像延迟超过探测窗口时，轻推退回后直接使用校准落点，不浪费探测等待。
指针隐藏、变成按钮高亮、检测结果不合理或画面较慢时，保留预计落点并点击一次。
自动/手动校准仍使用原有的长窗口和 12 单位探测。

点击后的一个 1.75 秒窗口内等待新帧，不重复等待画面静止，也不自动重试点击。
响应增加以下字段；`Phone.tap_verified()` 返回同一组字段，并保存在 `Phone.last_tap`：

```json
{
  "clicked": true,
  "pointer_seen": false,
  "screen_changed": true,
  "fresh": true,
  "latency": 2.36,
  "warning": null
}
```

`latency` 单位是秒；控制 API 的 `timing_ms.total` 包含校验与截图开销，单位是毫秒。
`clicked` 表示点击得到设备应答；`pointer_seen` 表示收到可信且合理的落点检测。
`screen_changed` 是视觉反馈，并不保证点中了预期按钮，所以 `effect_verified` 仍为 `false`。
未见变化时返回 `screen_changed: false` 和中文 `warning`，调用者应看图决定下一步。
批量操作的每个点击步骤也保留这些字段。

比较忽略顶部状态栏、已知指针位置、可辨认的灰色圆形指针和目标附近的按钮高亮，抑制 JPEG 噪声。
未知旧位置的中性灰色圆角空心高亮也可识别；只遮住轮廓及压缩边缘，保留内部内容变化。
高亮消失本身不算点击反馈，包括控制器刚启动、尚未记录旧指针位置的情况。
有板子时间戳时，点击前拍摄、点击后才到达的帧只更新比较基线，不作为点击反馈。
响应完全位于遮罩内、没有视觉变化或晚于等待窗口时会报告未见变化；动画也可能被计为变化。
观察校验可容忍至多两块很小的变化，因此不是逐像素一致性检查。

时序假镜像计入固件每 10 单位一份、每份 8 ms 的移动节拍，以及 60 ms 点击保持。
从原点移到 `(0.5, 0.44)` 的移动、唤醒和点击共需 636 ms；叠加 1.7 秒镜像延迟，
物理下限已是 2.336 秒，不能承诺 2.1 秒完成。完整 API 回归预算为固件耗时 + 镜像延迟 + 150 ms 开销，
这个目标点在两档延迟下都须低于 2.5 秒。短距离连续点击仍以 1–2 秒为目标。
测试不包括额外传输应答延迟或首次查询板子时钟的耗时，也不是已完成的真机性能测量。
真机仍需验证不同大小的按钮高亮、暗色菜单以及连续数字键的落点和耗时。
